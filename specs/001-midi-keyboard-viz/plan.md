# Implementation Plan: MIDI Keyboard Datasource Plugin

**Branch**: `001-midi-keyboard-viz` | **Date**: 2026-03-18 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/001-midi-keyboard-viz/spec.md`

## Summary

A purely frontend Grafana datasource plugin that connects to the browser's Web MIDI API and
provides four query modes — Raw messages (table), Notes (real-time active notes with sound),
Piano Timeline (state-timeline compatible event stream), and Drums (GM1-mapped hits with sound)
— all without any backend component. Each Grafana panel independently selects a MIDI device
and query mode via its query editor. Data is streamed to panels via RxJS Observables returned
from `query()`. Sound playback uses the Web Audio API (browser-native, no server required).

## Technical Context

**Language/Version**: TypeScript 5.9 (strict mode, `@grafana/tsconfig` base), React 18.3
**Primary Dependencies**: `@grafana/data ^12.4.0`, `@grafana/runtime ^12.4.0`,
`@grafana/ui ^12.4.0`, `@grafana/schema ^12.4.0` — all already in `package.json`;
`web-midi-test` (devDependency, for unit test mocking)
**Storage**: In-memory only — per-device rolling buffers and state maps, no persistence
**Testing**: Jest + `@swc/jest` + `web-midi-test` (unit); Playwright + `@grafana/plugin-e2e`

- `page.addInitScript()` MIDI mock (E2E)
  **Target Platform**: Browser (Chrome/Edge with Web MIDI API); Grafana >= 12.3.0
  **Project Type**: Grafana frontend datasource plugin (no backend)
  **Performance Goals**: MIDI events reflected in UI within 50ms (SC-002/SC-003);
  raw table readable at ≥200 MIDI msg/s (SC-004)
  **Constraints**: No backend; browser-native APIs only; all UI via `@grafana/ui`; no custom
  theming; `navigator.requestMIDIAccess` required (Chrome/Edge only)
  **Scale/Scope**: Single plugin instance; multiple panels per dashboard; one MIDI subscription
  per active panel; up to 128 simultaneous notes (full keyboard); 1000-row message buffer

### testDatasource()

Replaces HTTP health check with:

```typescript
async testDatasource(): Promise<TestDataSourceResponse> {
  if (!navigator.requestMIDIAccess) {
    return { status: 'error',
      message: 'Web MIDI API is not supported in this browser. Use Chrome or Edge.' };
  }
  try {
    await navigator.requestMIDIAccess();
    return { status: 'success', message: 'Web MIDI API is available' };
  } catch (err) {
    return { status: 'error', message: `MIDI access error: ${String(err)}` };
  }
}
```

### Observable streaming pattern

```typescript
query(options: DataQueryRequest<MidiQuery>): Observable<DataQueryResponse> {
  return new Observable<DataQueryResponse>((subscriber) => {
    const target = options.targets[0];
    if (!target?.deviceId) {
      subscriber.next({ data: [] });
      return () => {};
    }
    const unsub = this.midiAccess.subscribe(target.deviceId, (msg) => {
      this.updateState(target, msg);
      if (target.mode === 'notes' || target.mode === 'drums') {
        this.audioEngine.play(target.mode, msg);
      }
      subscriber.next({ data: [this.buildDataFrame(target)] });
    });
    subscriber.next({ data: [this.buildDataFrame(target)] }); // initial empty state
    return () => unsub();
  });
}
```

### Manual testing required (flag for task author)

The following acceptance criteria CANNOT be verified by automated tests and require a physical
MIDI keyboard. The task author must complete the manual checklist in quickstart.md before marking
the relevant story as done:

- US2 audio: pitch accuracy, velocity dynamics, note-off fade
- US4 audio: kick, snare, hi-hat, cymbal sounds
- SC-002/SC-003: <50ms latency (visual + audio) with real device
- Hot-plug detection (connect/disconnect while dashboard open)
- Browser autoplay policy prompt
